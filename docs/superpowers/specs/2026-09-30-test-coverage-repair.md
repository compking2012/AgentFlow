# 受控测试覆盖补齐

当前审查返工保留生产修复与测试期望迁移两条路径，并增加 `test_coverage_extension`：在原测试作者授权的现有测试文件、现有用例中补充断言与必要助手。它不改变任何已有断言、测试名称、测试配置或已接受需求。当前 WordBook 需要补齐真实 HTTP、级联删除和详情掌握程度断言，同时修复生产界面。

## 归属与证据

每条阻塞意见必须至少有一项处置。同一意见可交给不同作者，分别修复生产代码与补齐测试；同一意见与同一作者的重复处置仍拒绝。修复路径必须同时属于原作者和原计划范围，测试与生产作者不能相互代写。

覆盖补齐必须引用当前已接受、版本绑定的对应测试方案及准确原文。测试方案作为独立证据加入上下文，但不能据此批准测试期望迁移；迁移仍只由产品需求或架构契约支持。所有原审查意见保留，分析 Agent 无权豁免。

## 结构保护

标准 Babel 解析器只读取源码，不执行源码。覆盖补齐保持文件集合、文件模式和非授权文件完全不变；原测试清单、操作（不得 skip/only/todo）、参数与现有语句树保留。现有测试回调中的语句块只允许在尾部追加；原有助手、导入和顶层可执行语句不变。新增顶层内容仅允许无执行副作用的静态导入、函数和常量声明，且不得遮蔽旧标识符。新增内容不能修改旧绑定、退出进程或使旧断言提前跳过。

保护器证明原结构未被替换，并不自动证明新增断言正确。独立审查必须确认新增覆盖符合原方案，诊断测试通过后仍执行原正式测试门禁。

## 流程与恢复

覆盖补齐复用受控返工批次、原作者累计预算、源码组装、独立审查和诊断机制；不提前改变正常阶段的质量结论。同批生产与测试修复合并到同一新提交。

只读分析上下文可在新协议加载后升级，但仅限尚未派发修复动作、分析进程已停止的批次；原上下文完整归档，来源审查、源码及原文档身份必须保持。补充已接受测试方案后继续使用原分析工作项、重试记录和预算，不新建预算来绕过限制。更改或撤销证据仍拒绝。

## 验收

- 用 WordBook 的三条意见安排单元补齐、Web 补齐与前端生产修复；一条意见允许两名作者。
- 缺少方案依据、错引原文、跨文件权限、重复处置和用测试方案批准期望迁移均拒绝。
- 允许追加 HTTP/数据库/DOM 断言与助手；拒绝删除、修改、重排原断言，跳过用例、重绑断言对象、提前退出及配置修改。
- 归档旧上下文后原分析工作可重试；已派发动作或活跃分析不能升级上下文。
- 原迁移保护、预算累计、重启、诊断及正式质量门禁继续有效。

## 交叉审查补充约束

- 同一文件在一个并行批次中不能同时进行期望迁移和覆盖补齐；两种保护以不同子提交为基准，强行合并无法同时保留已验证文件。规划阶段明确拒绝这种组合，不生成必然无法验证的半批次。不同文件的两类任务仍可分配。
- 同一原作者的所有辅助任务共用剩余额度，启动时扣除未结算执行的预留；未知用量不视为已释放。每个执行上限同时受子任务和作者剩余额度限制。
- 既有超时自动续跑若批准辅助任务的新执行窗口，必须在一个事务中将相同增量记入子任务和原作者上限，并保留对应审计。历史用量、原策略、重试计数、模型和权限不变；重放不能重复追加。
- 升级旧分析上下文必须同时确认模型请求已停止。尚有活动或未经核验调用时，不能仅凭工作项停止状态升级。
- 组装诊断选用保护器前，重新核验各修复任务与控制器冻结规格；不能通过可变 payload 中的类别绕过覆盖保护回执。
