# Dashboard 安全复核记录

范围：`apps/dashboard/src/`、生成到 `src/agentflow/web/` 的静态资源，以及 `tests/browser/`。这是功能实现完成后的单独源码复核和浏览器验证步骤，由 Dashboard 实现 Agent 执行，不代表第三方安全评估。

## 复核方法

沿“启动码 → owner token → 请求出口”“外部产物 → 页面展示”“审批快照 → 提交”“矩阵计划 → 可交付状态”四条路径逐项检查，并搜索直接 HTML 注入、动态脚本、浏览器持久存储、网络请求出口和剪贴板调用。浏览器测试使用生产 API 与 SQLite，检查实际请求、DOM、存储和结果记录。

| 边界 | 源码判断及验证 |
| --- | --- |
| 启动码 | `main.tsx` 在 render、交换请求之前调用 `takeBootstrap()`；浏览器确认 URL fragment 已移除且请求 URL 不包含启动码。 |
| 会话保存 | `OwnerApi.#token` 为内存私有字段；Owner 凭据不写入持久存储或 Cookie，仅将受限续接票据按 origin+port 保存于标签页 sessionStorage。刷新优先续接，失效后重新建立本机会话。 |
| 直接连接 | `POST /api/v1/session/local` 无需启动码，要求精确 Host、同源 Origin、回环客户端与幂等键，拒绝跨站 Fetch Metadata；无 Cookie，管理接口仍要求 Bearer。任一本机进程可按此边界建立 Owner 会话，这不是本机用户/进程间隔离；不对非回环主机开放。 |
| 请求去向 | 唯一 fetch 出口固定到启动来源，仅接受 `/api/v1/`，拒绝路径穿越、反斜杠、外部来源及重定向；`credentials: omit`、`mode: same-origin`、`referrerPolicy: same-origin`。引用信息仅发送到同源；该策略避免 WebKit 将管理 POST 的 Origin 改写为 null，服务器仍严格核验 Origin。实际带认证请求均为控制来源。 |
| 事件流 | 使用认证 fetch；token 不进入 EventSource URL。连接断开后重连并保留当前游标，运行切换时中止旧连接。 |
| XSS/产物 | 页面无 `dangerouslySetInnerHTML`、`innerHTML`、eval 或动态 Function；报告经过 React 文本转义。含 script 标签的真实存储产物未执行。下载按 `.bin` 保存，不打开 iframe 或报告 URL。 |
| 预览内存 | 复核发现原实现先下载完整 Blob 后才检查大小；已改为同时检查 Content-Length 和逐块字节数，超过 1 MiB 取消 reader。大于限额的真实产物显示错误，无预览内容。 |
| 运行切换 | 复核发现资源读取在 effect 清除前可能保留上一请求的状态；已按请求路径即时隔离返回值，失败时撤下旧数据，切换时中止旧预览。浏览器验证先前产物、预览、平台结果和交付信息不会保留到新运行。 |
| 审核竞态 | 请求使用打开时的 revision/fingerprint；轮询发现变化即禁用，后端仍执行版本约束。浏览器触发真实返工后旧对话框不能批准。 |
| 审批语义 | 通过不会清除失败质量；驳回需原因和修改要求，返工目标仅列出当前依赖祖先。浏览器检查真实决定和工作项版本。 |
| 重试 | 同一未确认表单请求保持 Idempotency-Key；同步 ref 防止重复点击并发提交。最终命令去重由后端 Store 负责。 |
| 证据聚合 | 仅关联当前 run input 的唯一候选、绑定指纹和矩阵项检查。浏览器覆盖错配指纹、部分结果、未校验证据、零用例、旧输入版本及真实通过结果。 |
| 配对码 | 只在组件内存保存，显式显示或复制，关闭清除；浏览器验证真实 NodeService 配对记录不包含明文代码，页面无持久存储。 |
| 模型与权限 | 创建产品页仅在明确点击“保存并使用此模型”后向本机 owner API 提交；密码提交后清空，接口变化清空，不进入通用重试签名，也不回显 API Key。服务错误不显示凭据字段。缺失模型、运行组件或受阻执行环境不会显示为已就绪。 |
| 产品交付 | Product 状态完成且交付字段齐备后才显示下载/启动。源码通过 OwnerApi 同源认证下载为 Blob；拒绝为外部下载 URL 附加 owner token。 |
| 产品启动 | 只为服务返回的 running 状态提供本机 HTTP(S) 链接，拒绝外部主机、其他协议和 URL 内凭据。打开产品使用普通链接，不带 owner 认证；启动与停止通过固定 owner API 执行。服务端在返回 URL 前与运行期间核验真实子进程及已观察后代的监听地址和端口；这是持续观测检查，不能声称在内核层阻止了瞬时的非回环绑定。核验失败撤下地址并停止预览，无法确认停止时保留未知状态。 |

## 验证记录

- React/TypeScript 生产构建通过。
- 浏览器测试 TypeScript 检查通过；fixture Python Ruff 检查通过。
- 工作台与产品入口的 Chromium 测试验证鉴权、状态展示、表单重试及凭据清除；产品状态测试为明确的 UI 契约夹具，不能当作真实 Agent 研发验收。
- 生产依赖通过 npm 官方 registry 的 `npm audit --omit=dev` 检查，0 个已知漏洞。
- 桌面和窄屏页面截图人工查看，审核对话框通过 Tab、Shift+Tab、Escape 和返回焦点验证。

## 适用边界

浏览器只展示后端提供的数据，不能自行验证节点原始报告或 Git 对象。最终可交付门禁、凭据吊销、请求 Origin/Host、存储完整性、节点权限及 Git 发布由控制服务执行。本复核没有调用付费模型，也没有把 fixture 报告当作真实跨平台执行结果。已解锁同源页面内的任意脚本和本机恶意进程仍处于宿主信任边界内；前端内存私有字段不是对本机攻击者的隔离机制。
