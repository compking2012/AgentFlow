# AgentFlow 本地单用户 MVP v0.3：34 项计划验收

2026-09-18。控制应用采用本地SQLite WAL单写者、本地文件和纯Git；由同一所有者管理本机及显式配对的自有执行节点。MVP测试目标为Web、API、iOS、Android、Windows、macOS和Linux原生，共七类。当前仅提供设计与任务契约，未实现功能、调用模型或执行测试。

模型版本选择保持待确认；不重复发起询问，不静默切换或发起付费探针。OpenHands使用Chat Completions，Codex使用原生Responses/apply_patch，经本地代理连接获确认的模型配置。

## 验收原则

- LWP-01～38描述实现责任，LWP-28统一复核LAC-01～34。每个测试目标至少验证一组明确的框架、工具/驱动、OS和设备/桌面组合。
- 每个平台实际执行参考应用的正常路径及注入缺陷；零用例、执行器错误、未知结果、旧构建和证据缺失不通过。接口、方案、截图或模拟报告不替代真实执行。
- 每个产品按冻结的适用范围确定必需矩阵；七目标平台能力验收不等于要求每一个产品具备七种客户端。适用性与支持状态分开，失败后不得缩小必需分母。
- 管理UI/API只监听回环；自有节点使用独立受限执行通道，不取得owner、模型或Git发布权限。共享设备/桌面排他，独立资源可并行。

## 参考样本与两步冻结的责任

LWP-27先完成共享API、Web及五原生参考客户端的源码、依赖、构建配方、稳定控件、冻结业务期望及可控缺陷版本；平台适配器以这些产物开展验证。LWP-28使用其已冻结版本汇总最终验收，不负责在适配器验收完成后才准备样本。

运行时顺序为：功能与测试代码独立Review → LWP-15冻结SourceCandidate → LWP-29派发源码构建作业 → 各适配器返回产品与测试BuildArtifact → LWP-37冻结CandidateManifest → 对预构建输入执行正式单测和GUI/集成 → 汇总门禁。构建任务不要求尚不存在的最终候选摘要；正式测试不得引用尚未冻结或已变化的包。

构建与测试一体化工具必须使用经验证的分离执行方式，或证明实际运行产品/测试bundle与预构建清单完全一致。无法证明时阻塞该必需组合；测试重编译产生不同摘要时登记新的构建/候选并重验，不把该结果视为原清单通过。工作包依赖表达实现准备顺序，运行时仍须遵守上述产物前置条件。
